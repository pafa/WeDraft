# WeDraft 架构

## 网页与 AI 工具集（0.1.0 候选）

新增 `packages/core` 组合现有 parser、model、validation、renderer，统一 `renderArticle`、`validateInput`、`listTemplates` 与文章包导入导出 API。核心为纯函数，不读取文件、联网、保存草稿或调用模型。代码型消费者当前通过 pnpm workspace + TypeScript 构建使用它，尚未独立发布 npm 库。

```text
手工网页 ─┐
本地 CLI ─┼─ core → parser / model / validation / renderer → HTML + 检查结果
本地 MCP ─┘   └─ 原稿 + 模板版本 + 图片 ↔ .wedraft.zip
     ↑                                  ↕
   Skill 流程指导                    网页继续编辑
```

- `apps/web` 复用 Mac 的编辑器、撤回重做和双向映射；通过图片处理回调注入浏览器实现，Mac 默认路径不变。
- 网页文章和图片仅在页面内存暂存；刷新或关闭后清空，不提供文章库。旧候选的 IndexedDB `wedraft-web-v1` 不再读取、写入或删除，也不会访问 Tauri 数据库。Cookie 只保留默认模板；需要保留稿件时由用户导出文章包。
- CLI 明确处理文件输入、受限图片根目录与新目录输出；stdout JSON、stderr 错误，不覆盖旧目录。
- MCP 使用官方 SDK 的 stdio transport。默认三个纯工具，只有显式配置输出目录才提供 `export_article` 写文件工具；无 HTTP 服务、任意文件读取工具或微信发布能力。
- 文章包不在文件系统解压：只读受限大小、数量与路径的 ZIP 条目，检查 manifest 版本、图片类型、重复路径、UTF-8 和缺失资产。无法处理的 Markdown 阻止正式 HTML 输出，保留原稿用于修复。
- 网页使用 hash 路由分隔编辑器、模板库、AI 接入；七款模板共用目录，默认选择存入 Cookie，已有文章保留自身模板。手机预览固定逻辑尺寸，等比缩放后仍用逻辑坐标进行双向定位。
- 静态站点构建时携带自包含 CLI/MCP、安装器和 Skill。用户执行安装命令后才在本机登记 Codex 连接；网站不是远程 MCP 服务。
- 同一个版本的 CLI/MCP/网页共享模板。文章包记录 `schemaVersion`、`engineVersion`、`templateVersion`；模板版本不兼容时明确拒绝。

独立网页运行不需要 Rust。编译边界仍为现有 pnpm workspace 与 Tauri，未加入第二套包管理器。完整操作与限制见[网页指南](web-guide.md)、[AI 接入](ai-integration.md)。下文描述既有 Mac 1.1.2 架构。

## 产品边界

WeDraft 是 Apple Silicon macOS 单机应用，只负责：

```text
文本或富文本输入
  → 结构化文章
  → 小哈公社New默认主题
  → 网页版、iPhone、Android 实时预览
  → macOS 富文本剪贴板
  → 用户手动粘贴到微信公众号后台
```

应用没有微信 API、Token、IP 白名单、素材上传、草稿创建、Relay、云服务或发布历史。

## 前端

- React + TypeScript + Zustand；
- 解析纯文本、Markdown 和 HTML；
- 输出只含微信编辑器兼容标签及内联 CSS；
- 文章、作者、摘要、原文链接和内容检查；
- 仅在执行“复制排版”时写入本地文章历史；
- 单页模板即时切换；
- 微信公众号网页版、iPhone 17 Pro Max、Samsung Galaxy S26 Ultra 三端预览，正文区域独立滚动。
- 启动与新建文章时使用只读组件样稿驱动预览；鼠标经过不会清空，只有编辑区获得焦点后才进入输入状态，样稿不进入持久化与剪贴板流程。

## 原生层

Tauri/Rust 提供五类能力：

- SQLite 文章与偏好存储；
- 正文图片格式检查和本地缓存；
- 安全读取 App 图片目录；
- 单篇 Markdown 导出与全部文章 Markdown ZIP 导出（不打包图片缓存）；
- 使用 macOS 剪贴板同时写入 `text/html` 和 `text/plain`。

本地正文图片在复制前转换为 data URL 并写入 HTML。外部 HTTP(S) 图片保留原地址，界面会提示粘贴后检查。

## 模板：小哈公社

保留的“小哈公社”主题参数来自用户提供的四篇公众号文章的共同计算样式；当前默认是下文的“小哈公社New”：

| 元素 | 规则 |
| --- | --- |
| 正文 | 15px / 1.75 / 0.5px 字距 / 两端对齐 |
| 段落 | 左右 8px，段后 24px |
| 章节编号 | 25px、900 字重、斜体、`#F96E57` |
| 章节文字 | 15px、700 字重、`#FFA900` |
| 图片 | 100% 宽度、高度自适应 |

所有样式以内联 CSS 输出，减少从剪贴板粘贴到公众号后台时的样式丢失。

代码块作为独立结构化元素保存，输出为经过转义的 `pre > code`，保留换行与缩进，不执行其中内容。

“参考来源”标题与其后的列表会合并为独立结构化组件。两套模板分别定义参考卡片、标题和编号条目的内联样式。

模板入口和编辑器位于同一页面，主题切换会立即更新实时预览；只有“复制排版”会将当前文章写入历史。当前主题 ID 会本地保存并用于下次启动。

模板只保留“小哈公社”和“小哈公社New”两套。“小哈公社New”是默认模板，使用 16px 正文、1.82 倍行距，一级章节使用珊瑚红与 Pantone 158C `#F36C21`，正文重点使用墨绿，并针对章节编号、列表、引用、图片说明和来源说明提供独立语义样式。“小哈公社”的原始橙色 `#FFA900` 保持不变。

## 安全边界

- HTML 输入经过清理，删除脚本、事件属性和危险协议；
- 本地文件读取限制在 WeDraft 图片目录；
- 不请求或存储任何公众号密钥；
- 应用运行不依赖公网 IP；
- 用户在粘贴前可通过预览和内容检查确认结果。
