# WeDraft 开源与维护安排

现有 `pafa/WeDraft` 已采用 [MIT](../LICENSE) 开源，网页与 AI 工具集 `0.1.0` 以公开测试版部署至 [wedraft.xiaoha.org](https://wedraft.xiaoha.org)。部署源 SHA 与验收边界见[首发记录](releases/web-0.1.0.md)。继续执行现有的[Git 管理规则](git-workflow.md)，合并和后续发布均保留人工批准。

## 一个产品仓库，多个入口

继续在现有项目完成初版，共同维护排版规则、格式与测试。网页、CLI、MCP、Skill 放在同一个源码仓库，插件将来只做宿主安装包装。

| 目录 | 职责 |
| --- | --- |
| `packages/core` | 可复用的文章输入、检查、渲染与文章包 API。 |
| `packages/article-*`、`wechat-renderer`、`validation` | 现有解析、数据模型和模板实现。 |
| `apps/web` | 临时编辑、预览与文章包进出；不提供文章管理。 |
| `apps/desktop`、`packages/editor-ui` | Mac 应用及网页共用的编辑器组件。 |
| `packages/cli`、`packages/mcp` | 同一个核心的命令行与 AI 工具入口。 |
| `skills/format-with-wedraft` | 流程说明，避免复制排版实现。 |

暂不拆成多个独立 Git 仓库。共享组件已集中在 `packages/editor-ui`，不应复制后在两处各改一份。

## 首次公开记录与检查

按维护者 2026-09-19 的决定，**已将现有 [pafa/WeDraft](https://github.com/pafa/WeDraft) 仓库改为公开**，未建立第二个公开仓库，继续维护同一产品主线。网站地址为 `https://wedraft.xiaoha.org`；[部署材料](deployment.md)说明候选生成、资源校验与上线验收。

这一方式需要审查所有可见分支、标签、历史和 Actions 日志。GitHub 明确说明转公开会公开代码与工作流日志，公众也可以 fork；之后转回私有无法撤回已经产生的公开副本。[GitHub 可见性说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)。首次公开已核查当时的全部远端分支、标签、PR 引用、可达历史及工作流记录，未发现敏感资料阻塞；未删除或改写历史。

发布候选保留以下检查与材料：

1. 源文件白名单与完整 diff；排除文章数据库、私稿、图片缓存、导出文件、安装包、本机路径与凭据。
2. 保留必须的第三方声明。维护者明确排除的本地临时附件不核对来源、不纳入发布，也不作为交付阻塞项。
3. 维护者已选择 MIT，根目录已准备 LICENSE；第三方依赖沿用其各自原文，不能以项目许可证替代依赖声明。
4. README、上手示例、CONTRIBUTING、问题模板、SECURITY 联系方式和变更记录；只能填写真实可用的维护入口。
5. 干净环境安装、核心与传输测试、网页构建和浏览器交接验收；明确尚未验证的宿主和微信兼容性。
6. 维护者批准精确源版本、目标公开仓库与分发范围后，再执行公开推送、演示站部署或包发布。

## 公开后怎样管理

外部使用者提交 Issue 或 fork 后提出 PR；维护者决定需求是否进入范围，AI 可以实现、检查和整理审阅材料，合并及正式发布仍由维护者决定。一项改动围绕一个目标，核心行为改变必须同时检查网页、CLI 和 MCP。

公开仓库可以逐步启用 PR 检查与维护者审核，但这些是公开协作阶段的新规则，不作为已经完成的首次发布的额外完成条件。初期只保留必要的安装、类型、测试与构建检查；不从外部贡献者提交中执行带生产凭据的发布任务。

问题按缺陷、功能、模板、文档归类；优先处理内容丢失、图片丢失、格式不兼容和导入失败。没有维护承诺的功能不写进产品首页。漏洞报告使用已启用的 [GitHub 私密报告渠道](https://github.com/pafa/WeDraft/security/advisories/new)，不要求用户在公开 Issue 贴文章或账号信息。

## 版本与发布

新网页、core、CLI、MCP 初期按一个工具集版本协调，当前公开测试版为 `0.1.0`；Mac 已有基线是 `1.1.2`，本次不据此宣称桌面新版本已经发布。文章包 `schemaVersion` 与模板 `templateVersion` 单独记录，兼容性变化要明示。

一次正式发布关联一个确定源码提交、变更说明、测试记录以及产物校验和。演示站与可下载工具使用这一版本；开发分支改动不会自动上线。出现问题发布修复版本或切回保留的旧站点产物，不覆盖旧标签与旧安装包。

首版采用静态站点携带自包含 CLI / MCP 和一键安装器，源码安装作为开发者入口；后续再评估 npm 工具包和宿主插件。当前所有新包仍设 `private: true`，用于防止误发 npm；源码公开不等于 npm 包发布。安装资源包含许可证和第三方声明。

## 演示站与数据

网页部署为静态网站，不提供账户或文章管理。文章仅在当前页面内存暂存，刷新或关闭后清空；切换模板库和 AI 页面保留本次编辑，Cookie 只记住默认模板。需要保留内容时导出文章包。旧候选写入的浏览器记录不主动读取、删除或迁移。远程图片仍会请求来源网站，AI 宿主也有自己的数据处理规则，不能笼统承诺所有流程绝对离线。

网站由 Cloudflare Workers Static Assets 托管，无应用后台；未发布 npm 包。运营凭据不进入源码。当前配置关闭 Workers observability，不主动启用 Workers 请求日志；平台仍可能处理基础访问记录，不承诺零日志或未经核实的保留期限。后续如需远程 MCP，再单独设计认证、限流、存储期限和费用；它不是本地 MCP 首版的隐含能力。
