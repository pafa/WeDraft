# WeDraft 使用指南

本页适用于 Mac 应用 `1.1.2`。已公开的网页与 AI 工具集 `0.1.0` 测试版，分别见[网页使用指南](web-guide.md)和[AI 接入指南](ai-integration.md)。两种入口的草稿、图片处理和导出格式不同。网页版提供独立的七款模板库、AI 接入页和点击即开始输入的含图启动示例；AI 页面区分“整理 Markdown 后回网页调整”与“直接调用 Skill / MCP 得到可复制排版”两条流程。下文的启动样稿与历史行为特指已发布的 Mac 版。

WeDraft 在本机把文章整理成适合微信公众号的正文排版；最后的标题填写、图片检查、预览与发布仍在公众号后台完成。

当前源码的未发布修复包含：重新打开历史稿恢复该稿模板；历史列表和全部导出不再截断为最近 100 篇；编号同名标题导出时自动避让文件名；不支持的 Markdown 语法在复制前提示并定位。这些改动已经进入开源主线；“未发布”特指尚未发行新 Mac 安装包。详见[代码审核记录](code-quality-audit.md)。

## 1. 从一篇文章开始

启动或新建文章时，左右两栏会展示内置组件样稿，帮助你了解可用的标题、引用、列表、代码、来源与图片样式。鼠标经过不会清空样稿；点击编辑区或通过键盘让输入框获得焦点后，进入实际输入状态。样稿不会保存、复制或进入文章历史。

将完整稿件粘贴到左侧输入框：**第一行固定作为标题，第二行开始是正文**。正文会实时解析，并在右侧显示选中模板的排版。标题用于预览与文章识别，复制时不会混入正文。

```markdown
把文章排得更容易读

先用一个自然段交代核心观点。

## 1. 清楚的章节

正文中的 **关键结论** 可以适度强调。

> 一段需要单独呈现的引文。

- 一个并列要点
- 另一个并列要点

### 更具体的小节

说明：对正文的必要补充。

## 参考来源

1. 资料名称与出处
2. 另一条参考资料
```

编辑区的“复制Markdown规则”会复制当前应用支持的写作规则，你可以主动把它粘贴给外部 AI 工具。WeDraft 本身不调用模型，不会自动把文章发给 AI。

## 2. 编辑、定位与撤回

工具栏按内容类型提供标题、粗体、引用、列表、代码块、分隔线、说明、参考来源和正文图片入口。行级格式作用于光标所在行；可切换的格式再次点击可取消。粗体与行内代码支持包裹和解除。

- 左右两栏根据同一内容块同步定位，兼顾块内滚动进度；滚到顶部或底部时，另一栏也会贴齐同一端。
- 悬停右侧区块会高亮左侧对应行；左侧光标与编辑位置也会对应到右侧。
- 编辑区右侧的文章缩略导航条显示章节与正文结构，点击可以跳转。
- 右侧允许微调标题、正文、章节、引用、列表、表格单元格和参考来源等文字；离开编辑位置后写回 Markdown，并纳入同一套撤回/重做。
- 图片、代码和分隔线继续在左侧调整。长篇改写和结构重排也适合在左侧完成。

| 快捷键 | 操作 |
| --- | --- |
| `⌘ N` | 新建文章。 |
| `⌘ ⇧ C` | 复制当前排版。 |
| `⌘ Z` | 在编辑区撤回。 |
| `⌘ ⇧ Z` | 在编辑区重做。 |
| `⌘ B` | 在编辑区切换粗体。 |

## 3. 模板与三种视口

模板切换位于预览区顶部，切换不修改原文，选中的模板会保存为下次启动时的偏好。

| 模板 | 用途与基础样式 |
| --- | --- |
| **小哈公社New（默认）** | 适合手机长文阅读；16px 正文、1.82 倍行距，章节使用珊瑚红与橙色，重点使用墨绿。 |
| 小哈公社 | 保留原有主题；15px 正文、1.75 倍行距，以编号、橙色章节文字和黑色重点组织内容。 |

两套模板都支持章节、引用、列表、代码、图片说明和文末“参考来源”组件。更详细的参数和推荐写法见[小哈公社New 规范](next-edition-guidelines.md)。

“网页版 / iPhone / Android”是正文视口预览，便于比较行宽与阅读密度，不是独立的手机应用。微信后台与实际客户端可能调整样式，最终效果以粘贴后的微信预览为准。

## 4. 正文图片与来源

使用工具栏的“添加正文图片”选择本机文件，填写来源或选择“无来源插入”。图片会缓存到 WeDraft 的本地数据目录，并进入正文预览。

- 支持 JPG、PNG、WEBP 和 GIF。
- JPG、PNG、WEBP 长边超过 2400px 时按比例缩小；较大静态图片会尝试在本机重新编码，界面显示处理结果。
- GIF 保留原字节以维持动画，体积过大时提醒。
- 单张文件不得为空或超过 30 MiB，图像像素不得超过 4000 万；不符合限制时需先处理图片。
- 本地缓存图片在复制前嵌入富文本；外部 HTTP(S) 图片保留原地址，仍可能受来源站点或微信后台限制。

图片说明与来源用于辅助阅读；选择无来源不会自动生成出处，来源的准确性由作者确认。

## 5. 检查、复制与微信后台

点击“复制排版”前，应用会检查图片、表格、章节编号、分隔线和参考来源位置等兼容性问题。提示提供 Markdown 行号，点击可定位原文：

- **必须修正**的问题会阻止复制；修正后重新点击检查。
- **普通提醒**可以先修改，也可以确认后继续复制。

复制会同时写入 HTML 富文本与纯文本：公众号编辑器可读取排版，普通文本框可读取正文文字。复制不包含第一行标题，也不自动添加品牌动图、封面来源、感谢语或联系信息。

随后点击“打开公众号后台”，在浏览器中进入微信的图文编辑页面，填写标题并粘贴正文。逐项检查图片、来源、表格、章节和手机预览，再由你完成保存与发布。WeDraft 不创建微信草稿，也不执行发布。

## 6. 最近文章与导出

**只有执行“复制排版”后，当前文章才会进入本地历史。** 启动样稿、未命名或正文为空的文章不会作为有效历史保存。普通输入过程不应当作可靠的自动存稿机制，重要原稿请另外保存。

在“最近文章”中可以重新打开稿件、单篇删除或清空全部。删除会显示应用内确认，确认后更新列表；不要依靠源码仓库恢复删除的文章。

桌面 App 支持：

- **单篇导出**：保存为 Markdown `.md` 文件。
- **全部导出**：把文章 Markdown 文件放进 ZIP，同名标题会编号以保留每一篇。

导出不包含缓存图片文件。带有本地图片路径的 Markdown 离开这台电脑后可能无法加载图片，因此 ZIP 是文本导出，不是完整数据备份。若要保护全部历史、设置和图片，请使用自己的本机数据备份方案。

## 7. 常见问题

**为什么复制的内容没有标题？**

第一行标题交给公众号后台单独填写；复制功能只输出正文。

**Mac 前端预览与独立网页版有什么区别？**

`pnpm dev:desktop-web` 仅预览 Mac 的前端界面，原生图片缓存、历史、导出和系统剪贴板需要通过 `pnpm dev:desktop` 运行 Tauri App。`pnpm dev:web` 启动独立网页版，可添加本地图片、使用浏览器剪贴板并导出文章包，操作见[网页指南](web-guide.md)。

**必须联网吗？**

本地编辑与本机数据存储不依赖 WeDraft 云服务。加载外部图片链接、打开微信后台和最终发布需要相应网络连接。

**会同步到其他电脑吗？**

不会。GitHub 公开仓库只包含项目源码与内置演示素材，不同步用户稿件、图片、设置或剪贴板内容。

**为什么安装包没有 GitHub 下载链接？**

仓库已公开源码，但尚未提供正式 Mac 安装包下载。安装包在本机按批准的版本构建、验收和保存；当前为 Apple Silicon 构建，采用 ad-hoc 签名，未做 Developer ID 公证。
